# Маппинги Excel → канон

YAML в этой папке — шаблон конкретного файла, не автодетект.
Без «ок» владельца репозитория (Сергей) YAML не канон.

Ingest (Sprint 2) читает эти файлы и не угадывает колонки.

## Куда класть Excel

Копии боевых книг — в `data/incoming/` (каталог в git, сами `.xlsx` — нет).

Отклонённые строки ingest пишет в `data/rejects/` (тоже не в git).

## Какие YAML есть

| Файл | Коллекция | Статус |
|---|---|---|
| [budget.yaml](budget.yaml) | `budget_items` | канон v1, файл `БДР для индексации.xlsx` |
| `contracts.yaml` | `contracts` | нет, ждём выгрузку |
| `obligations.yaml` | `obligations` | нет, ждём выгрузку |

## Как читать YAML

- `source` — имя книги, лист, строки шапки, год, единица (`thousand_rub`).
- `columns` — колонка Excel → каноническое поле. Неизвестное уходит в `extra`.
- `blocks` — два дерева сметы (`production` / `management`), коды на листе с нуля в каждом.
- `hierarchy` — кто лист (точка), кто только путь; правило «деньги на родителе, дети-нули».
- `match_key` — склейка одноимённых статей для контроля.
- `skip_rows` — не ошибка (итоги, заголовки блоков).
- `rejects` — кандидат в лист, но битые данные.
- `open_questions` — не разветвлять код заранее.

Полные примеры родитель / лист и колонка лимита — в `docs/sprint-1-checklist.md` (пункт 4) и в комментариях `budget.yaml`.
