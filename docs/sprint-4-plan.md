# Sprint 4 — детальный план (RAG-ассистент)

Источник: `docs/PLAN.md` этап 4, `docs/FUNCTIONALITY.md`, `docs/sprint-3-plan.md`.

**Scope:** только бюджет. Золотой набор — вопросы по смете, не по договорам.

## 1) Цель спринта

Вопрос на естественном языке → ответ только по tool-результатам, со ссылкой на источник.

К концу спринта должно быть:

- Python-ассистент с tool calling к MCP;
- системный промпт: цифры только из tools, отказ если пусто, не путать факт и принятые;
- CLI-чат для отладки;
- `POST /chat` (вопрос → ответ + `sources`);
- золотой набор 20–30 вопросов по реальным данным без выдуманных сумм.

LLM runtime — уже имеющийся (LM Studio или иной OpenAI-compatible). Свой рантайм модели не пишем.

## 2) Входные условия (что уже готово после Sprint 3)

- MCP tools отвечают и сходятся с Excel на контрольных номерах.
- Индекс живой, не мок.
- Известен `LLM_URL` (LM Studio `/v1` или облако).

## 3) Границы Sprint 4

### Входит в Sprint 4

- оркестратор: вопрос → выбор tools → ответ;
- промпт и жёсткие правила (факт / принятые / `remain_free`);
- CLI-чат;
- `POST /chat` + `/health`;
- золотой набор и прогон;
- логи: вопрос, tools, hits, latency.

### Не входит в Sprint 4

- Telegram / веб-виджет (Sprint 6);
- упаковка всего контура в один compose (Sprint 5, можно задел);
- дообучение модели;
- запись в Excel из чата.

## 4) Sprint backlog (детализация задач)

## A. Клиент MCP и LLM

- HTTP-клиент к tools Sprint 3 (предпочтительно HTTP, не stdio, для сервиса).
- OpenAI-compatible chat completions с `tools`.
- Таймауты, 1–2 круга tool calls на вопрос (конфиг).

## B. Промпт и политика ответа

- Системный промпт:
  - сначала tools, потом текст;
  - цифры только из JSON tools;
  - пусто → «в индексе нет», без сумм;
  - «остаток» = `remain_free`, рядом подписать факт и принятые;
  - источники: файл, лист, номер договора / обязательства / статьи;
  - язык вопроса.
- Запрет юридических/бухгалтерских советов.

## C. Интерфейсы

- CLI: цикл ввода, печать ответа и sources.
- `POST /chat`: `{ "question": "..." }` → `{ "answer", "sources", "tools_used" }`.
- `/health`.

## D. Золотой набор

- 20–30 вопросов по боевому индексу, типы:
  - точный номер договора;
  - сумма обязательств по договору;
  - свободный остаток по статье / ветке;
  - факт vs принятые (оба числа в ответе);
  - отказ (несуществующий номер);
  - сквозной (договор → статья).
- Эталон: ожидаемые ключи (номер, сумма ± 0.01, must-not-hallucinate).
- Скрипт прогона или таблица ручной приёмки в `data/eval/gold.yaml`.

## E. Качество и отладка

- Логи структурированные.
- Разбор провалов золотого набора: промпт vs filter vs маппинг.
- Подключение агента LM Studio к MCP — опциональный стенд, не замена `POST /chat`.

## 6) Definition of Done (DoD) для Sprint 4

Спринт считается завершённым, если:

- CLI и `POST /chat` отвечают по живому MCP;
- на золотом наборе нет галлюцинированных сумм;
- точные вопросы (номер договора) попадают в правильную запись;
- вопрос без данных даёт отказ;
- в ответе на бюджетные вопросы не сливаются факт и принятые в одно «исполнено»;
- есть лог tool calls.

## 7) Демо-сценарий

1. Контур: Qdrant + ingest уже сделан + mcp + assistant + LLM.
2. CLI: «Что за договор {номер}?» — карточка и источники.
3. «Свободный остаток по {статья}» — `remain_free` как в Excel, рядом лимит / факт / принятые.
4. «Обязательства по договору {номер}» — сумма совпадает.
5. Несуществующий номер — отказ.
6. Тот же вопрос через `POST /chat`.
7. Показать таблицу золотого набора (pass/fail).

## 8) Риски Sprint 4 и меры

- Риск: локальная LLM плохо вызывает tools.
  - Мера: промпт + явные schema; запасной путь — облачная модель на том же MCP, индекс не трогаем.

- Риск: модель пересчитывает остаток сама.
  - Мера: в промпте «не считать, брать поле»; в оценке — сверка с Excel, не с формулой.

- Риск: золотой набор на синтетике.
  - Мера: только боевой индекс; иначе спринт не закрываем.

- Риск: бесконечные tool loops.
  - Мера: max rounds в конфиге.
