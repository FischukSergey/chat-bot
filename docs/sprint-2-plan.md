# Sprint 2 — детальный план (ingest → Qdrant)

Источник: `docs/PLAN.md` этап 2, `docs/ARCHITECTURE.md`, `docs/sprint-1-plan.md`.

**Статус:** закрыт 2026-09-18. Чек-лист: `docs/sprint-2-checklist.md`.

**Scope:** только бюджет. Договоры и обязательства не парсим и не индексируем.

## 1) Цель спринта

Довести Excel до идемпотентного индекса: парсинг по YAML, валидация, эмбеддинги, upsert в `budget_items`.

К концу спринта должно быть:

- CLI `python3 -m ingest load <file>` и `python3 -m ingest delete-source <file>`;
- коллекции Qdrant с payload indexes;
- повторный load того же файла не меняет число точек;
- сверка `remain_free` (Excel) с `лимит − принятые`, warning без перезаписи;
- выборка по `contract_number` в Qdrant находит ту же запись, что в Excel.

## 2) Входные условия (что уже готово после Sprint 1)

- Qdrant поднимается через `docker compose`.
- Есть утверждённые `data/mappings/*.yaml` и канон полей.
- Известны endpoint эмбеддингов и размер вектора.
- Боевые (или согласованные) Excel доступны оператору.

## 3) Границы Sprint 2

### Входит в Sprint 2

- парсер `.xlsx` по маппингу;
- сборка пути бюджета `l1`…`l5`, `ancestor_codes`, только листья в индекс;
- валидация строк, rejects, отчёт;
- сверка свободного остатка;
- текстовое представление + embeddings;
- создание коллекций и upsert со стабильным `id`;
- CLI load / delete-source;
- минимальные тесты парсера и сверки остатка.

### Не входит в Sprint 2

- MCP tools (Sprint 3);
- чат и tool calling (Sprint 4);
- HTTP-загрузка Excel оператором (Sprint 6);
- CSV (Sprint 6);
- пересчёт цифр статьи из реестра обязательств.

## 4) Sprint backlog (детализация задач)

## A. Модели и стабильный id

- Pydantic (или аналог) канонических записей: `BudgetItem`, `Contract`, `Obligation`.
- Стабильный `id`: хэш бизнес-ключа или `source_file + sheet + row`, как решено в маппинге.
- Нормализация `contract_number` — одна функция на все сущности.

## B. Парсер Excel

- Чтение `.xlsx` (`openpyxl` / `pandas`) с учётом строки шапки из YAML.
- Маппинг колонок → канон; неизвестные колонки → `extra` + в `text`.
- Бюджет: обход сверху вниз, накопление пути, индекс только листьев.
- Родительский итог в точку не пишем.
- Договоры и обязательства: построчно, связь через нормализованный `contract_number`.

## C. Валидация и отчёт

- Обязательные поля, числовые суммы, год, даты.
- Rejects в `data/rejects/` с причиной и номером строки.
- Сверка `remain_free`: `|excel - (limit - obligation)| > 0.01` → warning,
  в индекс — excel, `remain_free_source = excel`.
- Нет колонки остатка → compute + `remain_free_source = computed`.
- `remain_unexecuted`: из Excel или `obligation - fact`.
- Отчёт CLI: принято / обновлено / отклонено / warning.

## D. Эмбеддинги и текст

- Детерминированная склейка `text` (шаблон из ARCHITECTURE).
- Клиент embeddings (OpenAI-compatible, тот же, что будет у MCP).
- Батч-запросы, ретраи на 5xx, не писать точку без вектора.

## E. Qdrant

- Создание коллекций, если нет: размер вектора из конфига.
- Payload indexes: keyword (`contract_number`, `inn`, `article_code`,
  `ancestor_codes`, `status`, `year`, `source_file`), числовые суммы, даты.
- Upsert батчами.
- `delete-source` — filter по `source_file`.

## F. CLI и тесты

- `python3 -m ingest load <file> --mapping <yaml>`.
- `python3 -m ingest delete-source <file>`.
- Unit: нормализация номера, сверка остатка, классификация лист/родитель на фикстурах.
- Ручной прогон на боевом файле: повторный load, счётчики точек.

## 6) Definition of Done (DoD) для Sprint 2

Спринт считается завершённым, если:

- load боевого бюджета / договоров / обязательств отрабатывает с отчётом;
- повторный load не плодит дубли;
- `remain_free` в точке равен Excel; при расхождении с формулой есть warning;
- filter по `contract_number` находит ожидаемую запись;
- `delete-source` снимает точки файла;
- родители бюджета не лежат отдельными точками.

## 7) Демо-сценарий

1. Поднять Qdrant.
2. `load` бюджета → отчёт (листья, rejects, warning по остатку).
3. В Console открыть одну статью: лимит, факт, принятые, `remain_free`, путь `l1`…`l5`.
4. `load` договоров и обязательств; найти договор по номеру.
5. Повторить `load` бюджета — count коллекции тот же.
6. `delete-source` тестового файла — точки пропали; загрузить снова.

## 8) Риски Sprint 2 и меры

- Риск: кривая иерархия, листья определяются неверно.
  - Мера: фикстура 1 ветки из Sprint 1, тест «N листьев».

- Риск: смена модели эмбеддингов меняет размер вектора.
  - Мера: размер только из конфига; пересоздание коллекции явно, не молча.

- Риск: embeddings API недоступен (LM Studio выключен).
  - Мера: понятная ошибка CLI, точки без вектора не пишем.

- Риск: разные написания номера договора.
  - Мера: нормализация на ingest; в payload и сырое, и нормализованное поле, если нужно.
