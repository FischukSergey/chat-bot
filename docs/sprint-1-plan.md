# Sprint 1 — детальный план (каркас + маппинг Excel)

Источник: `docs/PLAN.md` этапы 0–1, `docs/ARCHITECTURE.md`, `docs/FUNCTIONALITY.md`.

**Scope:** только бюджет. Договоры и обязательства — не в работе.

## 1) Цель спринта

Поднять пустой контур и зафиксировать канон данных по **живым** Excel.
Без утверждённых маппингов Sprint 2 (ingest) не стартует.

К концу спринта должно быть:

- каталоги репозитория и `docker compose` с Qdrant;
- `.env.example` и общий конфиг коллекций / модели эмбеддингов;
- YAML-маппинги на бюджет, договоры, обязательства;
- правила иерархии бюджета (лист vs родитель) на реальных листах;
- протокол решений этапа 1 (колонки факта / принятых / остатка, статусы обязательств).

## 2) Границы Sprint 1

### Входит в Sprint 1

- каркас `ingest/`, `mcp_server/`, `assistant/`, `embed_svc/`, `deploy/`, `data/`, `configs/`;
- Qdrant в `docker compose`, volume, healthcheck;
- конфиги и `.env.example` (без секретов в git);
- разбор 1–3 настоящих файлов;
- `data/mappings/*.yaml` и список обязательных полей;
- решение по объединённым ячейкам, двустрочной шапке, итогам внизу листа.

### Не входит в Sprint 1

- парсер Excel и запись в Qdrant (Sprint 2);
- MCP-инструменты (Sprint 3);
- чат / RAG (Sprint 4);
- полный compose с mcp и assistant (Sprint 5);
- синтетические Excel «вместо» боевых — только как временная заглушка на дни 1–2, не как DoD.

## 3) Sprint backlog (детализация задач)

## A. Каркас репозитория

- Создать целевые каталоги из `docs/ARCHITECTURE.md`.
- Заготовки модулей:
  - `ingest/` — Python-пакет, пустой `__main__` / README «load в Sprint 2»;
  - `mcp_server/` — `go.mod`, заглушка `main.go`;
  - `assistant/` — заглушка пакета.
- Корневые `README.md` (как запускать Qdrant) и `.gitignore`
  (`data/incoming/`, `data/rejects/`, `.env`, `.venv/`).
- Python: `requirements.txt` или `pyproject.toml` (пока зависимости каркаса).
- Go: минимальный `go.mod` с модулем проекта.

## B. Qdrant и local DX

- `deploy/docker-compose.yml`: сервис `qdrant`, порт 6333, persistent volume.
- Healthcheck Qdrant (`/readyz` или эквивалент).
- `.env.example`: `QDRANT_URL`, `EMBEDDINGS_URL`, `LLM_URL`, имена коллекций,
  размер вектора (заполнить после выбора модели на этапе 1).
- `configs/default.yaml` (или аналог):
  - коллекции `budget_items`, `contracts`, `obligations`;
  - лимиты search (1…20);
  - порог score (черновик);
  - epsilon сверки остатка `0.01`.

## C. Источники Excel

- Получить 1–3 файла: бюджет, реестр договоров, реестр обязательств.
- Сложить **копии** в `data/incoming/` (не в git) или описать путь, если файлы секретные.
- На каждый файл: имя листов, строка шапки, есть ли итоги / объединённые ячейки.
- Зафиксировать, какой файл — источник правды по статье (лимит, факт, принятые, `remain_free`).

## D. Канон и маппинги

- Сверить колонки с каноном `docs/ARCHITECTURE.md`:
  - бюджет: лист, путь `l1`…`l5`, `year`, лимит / факт / принятые / `remain_free`;
  - договоры: номер, контрагент, ИНН, даты, сумма, статья;
  - обязательства: ключ, договор, статья, сумма, статус `accepted` / `reflected` / `cancelled`.
- YAML на тип файла: исходная колонка → каноническое поле, тип, обязательность.
- Правила иерархии: какие строки — только путь, какие — листья (точки).
- Нормализация номера договора (черновик правила: пробелы, `/` vs `-`).
- Записать открытые развилки в конец маппинга, не разветвлять код заранее.

## E. Решения этапа 1 (закрыть письменно)

1. Какие листы — источник правды.
2. Провайдер эмбеддингов и LLM (LM Studio endpoint или иной OpenAI-compatible).
3. Нужен ли stdio MCP в Cursor сразу или только HTTP.
4. Кто грузит файлы и как часто.
5. Как в Excel называются факт, принятые, свободный остаток;
   чем в реестре «принято» отличается от «отражено».

## F. Документация спринта

- Поправить `ARCHITECTURE.md` / `FUNCTIONALITY.md`, если живые колонки расходятся с каноном.
- Короткий `data/mappings/README.md`: как читать YAML, куда класть xlsx.
- Чек-лист спринта закрывается только с реальными файлами.

## 5) Definition of Done (DoD) для Sprint 1

Спринт считается завершённым, если:

- `docker compose up` поднимает Qdrant, healthcheck зелёный;
- есть YAML-маппинг на каждый согласованный тип файла;
- для бюджета описано, какие строки индексируются как листья;
- протокол решений этапа 1 заполнен;
- в git нет секретов и боевых xlsx;
- Sprint 2 может писать парсер, не угадывая колонки.

## 6) Демо-сценарий

1. Клонирование / чистая машина (или `docker compose down -v` + up).
2. Qdrant ready.
3. Показать три mapping YAML и один лист бюджета: «это родитель, это лист».
4. Показать, какая колонка — `remain_free`, какая — факт, какая — принятые.
5. Показать `.env.example` и выбранный embeddings/LLM endpoint.

## 7) Риски Sprint 1 и меры

- Риск: Excel не отдают вовремя.
  - Мера: дни 1–3 — только каркас; с дня 4 без файлов спринт не закрываем, сдвигаем, синтетикой DoD не подменяем.

- Риск: шапка плывёт между выгрузками.
  - Мера: маппинг на шаблон файла, не «вечный автодетект».

- Риск: родители с собственной суммой, не равной детям.
  - Мера: отдельное правило в mapping README; по умолчанию итог родителя не индексируем.

- Риск: спор про статусы обязательств.
  - Мера: закрыть в протоколе дня 8, не оставлять на Sprint 2.
