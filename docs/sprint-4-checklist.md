# Sprint 4 Checklist

Источник: `docs/sprint-4-plan.md`.

## 1) Подготовка

- [ ] MCP Sprint 3 отвечает на контрольных номерах.
- [ ] `LLM_URL` доступен (LM Studio или иной).
- [ ] Живой индекс, не мок tools.

## 2) Оркестратор

- [ ] HTTP-клиент к MCP tools.
- [ ] LLM-клиент с tool calling.
- [ ] Ограничение числа кругов tool calls.
- [ ] Системный промпт: только факты tools, отказ, факт ≠ принятые, sources.

## 3) Интерфейсы

- [ ] CLI-чат.
- [ ] `POST /chat` (`answer`, `sources`, `tools_used`).
- [ ] `/health`.
- [ ] Структурированные логи (вопрос, tools, hits, latency).

## 4) Золотой набор

- [ ] 20–30 вопросов по боевым данным.
- [ ] Типы: номер, сумма обязательств, остаток статьи, факт vs принятые, отказ, сквозной.
- [ ] Эталоны из Excel.
- [ ] Прогон и таблица pass/fail.
- [ ] Нет галлюцинированных сумм на прогоне.

## 5) Документация

- [ ] `docs/api-sprint-4.md`.
- [ ] Промпт лежит в репозитории (не только в голове).
- [ ] `data/eval/gold.yaml` (или эквивалент).

## 6) Критерии готовности (DoD)

- [ ] CLI и `POST /chat` работают на живом MCP.
- [ ] Точный номер договора → правильная запись.
- [ ] Пустой индекс/номер → отказ.
- [ ] Факт и принятые в бюджетных ответах разведены.
- [ ] Золотой набор прогнан, провалы записаны.

## 7) Демо

- [ ] Четыре живых вопроса в CLI (карточка, остаток, обязательства, отказ).
- [ ] Тот же отказ/успех через `POST /chat`.
- [ ] Показать pass/fail золотого набора.
- [ ] Зафиксировать known limitations Sprint 4.
