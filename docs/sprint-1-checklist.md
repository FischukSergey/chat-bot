**Смета — шапка и деньги**

- Единица: тыс. рублей (`amount_unit = thousand_rub`).
- Шапка многострочная: строки **7–11**. Merge на именах и шапке периодов.
- `S` — 2024 факт, всего; `W` — 2025 план, всего; **`AA` — 2026 план, всего**.
- `AE+` — кварталы 2026; рядом разрез транспортировка / СУГ / прочие.
- В индекс: `year=2026`, `limit_amount` ← **AA (Всего)**.
- Факт 2024 и план 2025 — только `extra`, не `fact_amount`.
- Разрез по видам деятельности — `extra` / аналитика, не отдельные точки.

**Два блока расходов (хранить раздельно)**

| | Производственные | Управленческие |
|---|---|---|
| Заголовок | стр. 12 | стр. 141 |
| Статьи | 13–139 | 143–250 |
| Итог | стр. 140 «ИТОГО производственные» | стр. 251 «ИТОГО управленческие» |
| `expense_kind` | `production` | `management` |

Код на листе собирается из A–G и **в каждом блоке начинается заново**.
Без префикса блока `article_code` столкнётся (`1` = «Материальные расходы» в обоих).
Канон: `article_code = {expense_kind}:{код листа}`, например `production:1.8.2`.

Имя — H/I/J/K из‑за объединений.

Пропускать: заголовки блоков, строки «ИТОГО …», стр. 142 (мусор шапки),
стр. 233–237 (пустые хвосты нумерации без имени).

**Иерархия и листья**

- Глубина 1…4. В лимит «до 5» укладывается.
- Родитель, чья сумма = итог детей — в индекс не писать (иначе двоим план).
- Строка без детей — лист, даже на уровне 1.
- Если у узла сумма есть, а **все потомки нули/пусты** — индексируем родителя,
  детей-заглушки не пишем. Иначе потеряем ФОТ и соцвзносы:
  - `production:2` «Расходы на оплату труда» = 3 189 637, дети `2.1`/`2.2` = 0;
  - `production:3` и `management:3` «Отчисления в фонды…» — деньги на родителе;
  - `management:2` — деньги на ребёнке `2.1` «Фонд оплаты труда», родителя не пишем.
- Нулевые настоящие листья без детей индексируем (статья должна существовать).
- Пример родителя: `production:1` «Материальные расходы», `production:1.8` «Коммунальные услуги».
- Пример листа: `production:1.8.2` электроэнергия, `management:1.1.2` электроэнергия.

**Контроль по одноимённым статьям**

Точки храним раздельно (`expense_kind`). Для бюджетного контроля одноимённые
листья **суммируются** по `match_key`:

- по умолчанию = нормализованное имя (`ё→е`, lower, схлопнутые пробелы);
- для слишком общих имён (`прочие`, `прочее`) — `нормаль(родитель) / нормаль(имя)`;
- алиас: «оформление в собственность земли, других ОС» ≈
  «оформление в собственность земли и других ОС».

Пока нет реестра обязательств, `budget_article` на будущих договорах/обязательствах
класть на `match_key`, не на сырой код листа.
Вопрос без уточнения блока («лимит по охране») — сумма по `match_key`.
«Управленческие на охрану» — фильтр `expense_kind=management`.

**Лимит / факт / принятые / `remain_free`**

- В этом файле **нет** принятых обязательств, отражённого факта контроля и свободного остатка.
- «Факт» в шапке — факт **прошлого года**, не `fact_amount`.
- `remain_free` из этого Excel не брать и не считать. Сценарий остатка — когда появится реестр контроля.
- Сверка ФинРез: себестоимость 2026 = итог производственных;
  управленческие 2026 = итог второго блока. ФинРез не грузить.

**1. Листы — источник правды**

- Бюджет v1: `data/incoming/БДР для индексации.xlsx`, лист **Смета затрат**.
- `limit_amount` ← колонка **AA** (план 2026, Всего).

- Листы **ФинРез** и **Оценочные показатели** не индексировать.
- Договоры и обязательства: файлов нет, источник правды появится с выгрузками.

**2. Эмбеддинги и LLM**

- Провайдер: **LM Studio**, один OpenAI-compatible endpoint `http://127.0.0.1:1234/v1`
  (поля `EMBEDDINGS_URL` / `LLM_URL` в `.env`).
- Ingest и MCP читают **одну и ту же** embedding-модель из конфига, не «что сейчас в UI Studio».
- Локальный выбор (только `.env`): `LLM_MODEL=qwen/qwen3.6-35b-a3b`,
  `EMBEDDINGS_MODEL=text-embedding-qwen3-embedding-0.6b`, `VECTOR_SIZE=1024`.
  В `.env.example` имён не дублируем.
- Перед первым ingest поля обязательны и ненулевые; коллекцию с `vector_size=0`
  не создавать. Размер проверять как `len(embedding)` у `POST /v1/embeddings`.
- Смена embedding-модели = новый размер или другое пространство → дроп коллекции
  и полная переиндексация. Код «на несколько моделей сразу» не плодить.

**3. Транспорт MCP**

- Sprint 1 Cursor через stdio **не подключаем** — сервера ещё нет.
- Когда появится MCP (Sprint 3): **оба** транспорта, один слой `tools`.
  - HTTP (streamable) — для `assistant` в Docker и ручных вызовов.
  - stdio — для Cursor / LM Studio, не блокер Sprint 1 и не замена HTTP-чата.
- Ассистент (Sprint 4) ходит в tools по HTTP, не через stdio.

**4. Оператор и частота**

- Оператор загрузки: владелец репозитория (Сергей).
- Способ v1: файл в `data/incoming/` + CLI ingest (`task ingest`, когда появится в Sprint 2).
- HTTP-загрузка — Sprint 6, не раньше.
- Частота: по факту новой версии Excel, без cron. Смета — годовой цикл плюс
  правки, когда приносят новый файл. Повторный ingest того же файла — upsert,
  не вторая копия.
- Реестры договоров / обязательств: расписание появится вместе с файлами.

**5. Факт / принятые / остаток / статусы**

- В текущей смете колонок принятых, отражённого факта и `remain_free` нет.
- «Факт» в шапке (`S`) — факт **2024**, не `fact_amount` контроля.
- `remain_free` из этого Excel не брать и не считать.
- Статусы обязательств (`accepted` / `reflected` / `cancelled`) — канон
  `ARCHITECTURE.md`; в живом реестре не проверены, пока файла нет.
